## ۱. پیش‌نیازها

- **اودو ۲۰** (Community یا Enterprise). درگاه وستا فقط به ماژول `payment` وابسته است و در فروشگاه اینترنتی، پورتال مشتری، لینک پرداخت فاکتور و سفارش فروش کار می‌کند.
- **دامنه با HTTPS** (مثلاً `https://shop.example.ir`). بانک‌ها مشتری را به همین آدرس برمی‌گردانند.
- **IP عمومی ثابت** برای سرور اودو. بانک‌ها فقط به درخواست IP ثبت‌شده پاسخ می‌دهند. اگر پشت CDN یا پروکسی هستید، IP **خروجی** سرور (همان IPی که سرور با آن به اینترنت وصل می‌شود) را ثبت کنید، نه IP CDN.
- **ساعت سرور هماهنگ با NTP** (برای بانک ملی/سداد الزامی است).
- حداقل یک **cron worker**: `max_cron_threads = 1` یا بیشتر در فایل تنظیمات اودو.
- ارز **ریال (IRR)** فعال باشد. اگر حساب‌ها به **تومان** است و ارز سفارشی `IRT` دارید، آن هم پشتیبانی می‌شود (هر تومان = ۱۰ ریال).

## ۲. نصب

1. فایل زیپ را باز کنید. پوشه‌ها را در یک مسیر ماژول اودو بگذارید، مثلاً:
   ```
   /opt/odoo/custom-addons/vesta-payment-iran/
   ├── vesta_payment            ← اپ «درگاه وستا» (لازم)
   ├── vesta_payment_mellat     ← بانک ملت
   ├── vesta_payment_saman      ← بانک سامان
   ├── vesta_payment_sadad      ← بانک ملی (سداد)
   ├── vesta_payment_pasargad   ← بانک پاسارگاد
   └── vesta_payment_parsian    ← بانک پارسیان
   ```
2. مسیر را به `addons_path` در فایل تنظیمات اودو اضافه کنید:
   ```ini
   addons_path = /opt/odoo/odoo/addons,/opt/odoo/custom-addons/vesta-payment-iran
   ```
3. اودو را راه‌اندازی مجدد کنید. در اودو: **برنامه‌ها ← به‌روزرسانی فهرست برنامه‌ها**.
4. **درگاه وستا** (Vesta Gateway) را نصب کنید. بعد از منوی **درگاه وستا ← بانک‌ها** هر بانکی را که لازم دارید با دکمه‌ی **نصب** اضافه کنید (یا مستقیم ماژول `vesta_payment_<bank>` را نصب کنید).
5. برای رابط فارسی: **تنظیمات ← زبان‌ها ← فارسی** را فعال کنید.

> روی ماشین بدون رابط گرافیکی:
> ```bash
> odoo -c /etc/odoo/odoo.conf -d mydb -i vesta_payment,vesta_payment_mellat,vesta_payment_saman,vesta_payment_sadad,vesta_payment_pasargad,vesta_payment_parsian --stop-after-init
> ```

## ۳. حالت آزمایشی (سندباکس)

در حالت آزمایشی هیچ پول واقعی جابه‌جا نمی‌شود. درخواست‌ها به `https://sandbox.banktest.ir` می‌روند که پاسخ همه‌ی بانک‌ها را شبیه‌سازی می‌کند؛ حتی خطاها (انصراف مشتری، خطای Verify، قطع ارتباط ۶۵ ثانیه‌ای) را می‌توانید روی صفحه‌ی پرداخت آزمایشی انتخاب کنید.

1. در [banktest.ir](https://banktest.ir) حساب بسازید و برای هر بانک یک **پذیرنده‌ی آزمایشی** ایجاد کنید. اطلاعات اتصال در صفحه‌ی «مشخصات پذیرنده» نمایش داده می‌شود.
2. در اودو: **درگاه وستا ← بانک‌ها ← پیکربندی** (روی کارت بانک).
3. در زبانه‌ی **پیکربندی**، اطلاعات پذیرنده‌ی آزمایشی را وارد کنید:

   | بانک | فیلدها در اودو | از صفحه‌ی banktest.ir |
   |---|---|---|
   | ملت | شناسه ترمینال، نام کاربری، رمز عبور، وب‌سرویس (REST پیشنهادی) | شناسه پذیرنده، نام کاربری، کلمه عبور |
   | سامان | شناسه ترمینال | شناسه پذیرنده |
   | ملی (سداد) | شناسه پذیرنده، شناسه ترمینال، کلید تراکنش | شناسه پذیرنده، شناسه ترمینال، کلید تراکنش |
   | پاسارگاد | شماره ترمینال، نام کاربری، رمز عبور | شناسه ترمینال، نام کاربری، کلمه عبور |
   | پارسیان | پین | شناسه پذیرنده (PIN) |

4. بخش **سرور بانک** را بررسی کنید: «سرور آزمایشی» به‌طور پیش‌فرض `https://sandbox.banktest.ir` است.
5. دکمه‌ی **حالت آزمایشی** و بعد **آزمایش اتصال** را بزنید. پیام سبز یعنی رمزها درست است.
6. یک خرید آزمایشی انجام دهید. در صفحه‌ی پرداخت آزمایشی گزینه‌ی «بدون مشکل» را بگذارید و «ثبت روند تراکنش» و سپس «تکمیل فرایند خرید» را بزنید. باید به صفحه‌ی «پرداخت شما انجام شد» برگردید و تراکنش در **درگاه وستا ← پرداخت‌ها** با رسید دیجیتال دیده شود.
7. سناریوهای خطا را هم امتحان کنید: انصراف کاربر، خطای Verify، تایم‌اوت. تراکنش باید به ترتیب «لغو»، «خطا» و «در انتظار بانک» شود (در حالت تایم‌اوت، کران هر ۵ دقیقه دوباره تلاش می‌کند).

> **نکته:** در حالت آزمایشی، کنار نام بانک در صفحه‌ی پرداخت یک نشان هشدار دیده می‌شود. درگاهی را که در حالت آزمایشی است روی سایت عمومی باز نگذارید؛ بعد از آزمایش آن را «غیرفعال» یا «عملیاتی» کنید.
> **نکته:** پاسارگاد کمتر از ۱۰٬۰۰۱ ریال را نمی‌پذیرد.

## ۴. فعال‌سازی عملیاتی (سرور اصلی بانک)

### ۴.۱ آنچه از بانک می‌گیرید

برای هر بانک، بعد از عقد قرارداد پذیرندگی اینترنتی (از شعبه یا شرکت پرداخت):

| بانک | شرکت پرداخت | اطلاعاتی که می‌گیرید | آنچه به بانک می‌دهید |
|---|---|---|---|
| **ملت** | به‌پرداخت ملت | شماره ترمینال، نام کاربری، رمز عبور | IP سرور، **دامنه‌ی سایت** (آدرس بازگشت باید روی همین دامنه باشد) |
| **سامان** | پرداخت الکترونیک سامان (سپ) | شماره ترمینال (MID)، رمز پنل گزارش | IP سرور |
| **ملی** | سداد | شناسه پذیرنده، شناسه ترمینال، کلید تراکنش | IP سرور، آدرس سایت |
| **پاسارگاد** | پرداخت الکترونیک پاسارگاد (پپ) | شماره ترمینال، نام کاربری، رمز عبور | IP سرور |
| **پارسیان** | تجارت الکترونیک پارسیان (پک) | پین (LoginAccount) | IP سرور |

### ۴.۲ تنظیم اودو

1. **تنظیمات ← فنی ← پارامترهای سیستم**: `web.base.url` را روی آدرس HTTPS سایت بگذارید (مثلاً `https://shop.example.ir`) و پارامتر `web.base.url.freeze` را با مقدار `True` بسازید. آدرس بازگشت بانک از همین ساخته می‌شود:
   ```
   https://shop.example.ir/payment/vesta/<bank>/return/<order_id>/<hmac>
   ```
2. پشت nginx: `proxy_mode = True` در تنظیمات اودو و هدرهای `X-Forwarded-Proto` و `X-Forwarded-Host` در nginx.
3. در فرم بانک (درگاه وستا ← بانک‌ها ← پیکربندی) اطلاعات **اصلی** بانک را جایگزین اطلاعات آزمایشی کنید.
4. **فعال‌سازی عملیاتی** را بزنید. اودو بررسی می‌کند همه‌ی فیلدهای لازم پر باشند.
5. **آزمایش اتصال** را بزنید. این کار پولی جابه‌جا نمی‌کند (فقط یک توکن بی‌استفاده می‌گیرد یا وارد سرویس می‌شود) و نشان می‌دهد رمزها و **IP سرور** پذیرفته شده‌اند.
6. یک خرید واقعی با مبلغ کم انجام دهید و بعد از دیدن رسید، آن را **استرداد** کنید (سامان، پاسارگاد، پارسیان) یا از پنل بانک برگشت بزنید.

### ۴.۳ برگشت به حالت آزمایشی

هر وقت لازم شد، دکمه‌ی **حالت آزمایشی** را بزنید. اطلاعات اصلی پاک نمی‌شود ولی درخواست‌ها به سرور آزمایشی می‌روند؛ پس برای آزمایش واقعی، اطلاعات پذیرنده‌ی آزمایشی را هم وارد کنید یا یک نسخه‌ی تکراری (Duplicate) از درگاه بسازید.

## ۵. روشن و خاموش کردن بانک‌ها

منوی **درگاه وستا ← بانک‌ها** برای هر بانک یک کارت دارد:

| دکمه | کار |
|---|---|
| **پیکربندی** | فرم کامل درگاه: اطلاعات اتصال، روش پرداخت، محدودیت کشور و مبلغ، پیام‌ها |
| **فعال‌سازی عملیاتی** | انتشار درگاه روی سرور اصلی بانک (با تأیید) |
| **حالت آزمایشی** | انتشار روی سندباکس |
| **غیرفعال کردن** | پنهان کردن از مشتری؛ تنظیمات و تراکنش‌ها می‌مانند |
| **آزمایش اتصال** | بررسی رمز، IP و دسترسی بانک؛ نتیجه روی کارت می‌ماند |
| **پرداخت‌ها** | تراکنش‌های همین بانک |
| **نصب** | نصب ماژول بانک (برای بانک‌های نصب‌نشده) |

روی هر کارت آمار ۳۰ روز گذشته (تعداد و مبلغ پرداخت موفق، ناموفق‌ها و «در انتظار بانک») دیده می‌شود. اگر اطلاعات اتصال ناقص باشد، هشدار زرد نمایش داده می‌شود.
ترتیب نمایش بانک‌ها در صفحه‌ی پرداخت مشتری از فیلد «ترتیب» درگاه (Sequence) در فهرست **پیکربندی ← درگاه‌های بانکی** تعیین می‌شود.

### ۵.۱ مسیریابی هوشمند تراکنش

منوی **درگاه وستا ← مرکز کنترل** صفحه‌ی اصلی اپ است. در بخش **مسیریابی خودکار** یکی از چهار حالت را انتخاب کنید:

| حالت | تنظیم لازم روی هر بانک | نتیجه |
|---|---|---|
| **انتخاب مشتری** | فقط ترتیب (دکمه‌های ↑ ↓) | همه‌ی بانک‌های فعال به همین ترتیب نمایش داده می‌شوند |
| **توزیع وزنی** | **وزن** (۰ تا ۱۰۰) | هر پرداخت به بانکی می‌رود که بیشترین کسری را نسبت به سهمش دارد. با وزن‌های ۴۰/۳۰/۱۵/۱۰/۵، از هر ۱۰۰ پرداخت ۴۰تا ملت، ۳۰تا سامان و… |
| **چرخشی** | **نوبت** (تعداد پرداخت پیاپی) | بانک‌ها به ترتیب نوبت می‌گیرند؛ با نوبت ۳ برای ملت و ۱ برای بقیه: ملت، ملت، ملت، سامان، ملی، … |
| **اولویت با جایگزین** | فقط ترتیب | بانک اول همه‌ی پرداخت‌ها را می‌گیرد؛ وقتی متوقف شد یا سقفش پر شد، بانک بعدی |

- **بانک‌های دیگر هم نمایش داده شوند:** خاموش باشد، مشتری فقط بانک انتخاب‌شده را می‌بیند (اگر روش پرداخت دیگری فعال نباشد، همان از قبل انتخاب شده است). روشن باشد، بانک انتخاب‌شده اول و بقیه زیر آن می‌آیند.
- **سقف روزانه:** «سقف تعداد / روز» (پرداخت موفق) و «ریال / روز» (مبلغ دریافتی). وقتی پر شود، آن بانک تا پایان روز (به وقت تهران) از مسیریابی کنار می‌رود. ۰ یعنی بدون سقف.
- **سلامت:** بانکی که ۳ بار پیاپی توکن صادر نکند (قطعی، رمز یا IP نادرست)، ۱۰ دقیقه کنار گذاشته می‌شود و نشان قرمز «متوقف پس از خطاهای پیاپی» می‌گیرد. دکمه‌ی **ادامه** آن را زودتر برمی‌گرداند. ردّ شدن به‌خاطر مبلغ سفارش حساب نمی‌شود.
- اگر همه‌ی بانک‌ها متوقف یا پر باشند، همه نمایش داده می‌شوند تا مشتری بی‌درگاه نماند.
- **پرداخت‌های بعدی:** ۲۴ تصمیم بعدی مسیریابی را با لوگوی بانک می‌بینید؛ با هر تغییر وزن یا نوبت، همان لحظه به‌روز می‌شود.
- **سهم امروز / هدف:** برای هر بانک، سهم واقعی امروز کنار سهم هدف نمایش داده می‌شود. توزیع وزنی بانکی را که عقب افتاده جلو می‌اندازد تا به سهمش برسد.

> تصمیم مسیریابی فقط به پایگاه‌داده بستگی دارد (پرداخت‌های امروز، وزن، نوبت، سقف و سلامت)؛ پس صفحه‌ی پرداخت و پیش‌نمایش مرکز کنترل همیشه یکی‌اند، و چند مشتری هم‌زمان هم به بانک یکسان می‌روند.

## ۶. کار روزانه

- **پرداخت‌ها:** منوی **درگاه وستا ← پرداخت‌ها** همه‌ی تراکنش‌های بانکی را با رسید دیجیتال، شماره مرجع (RRN)، شماره پیگیری، شماره کارت پوشیده و وضعیت تأیید بانک نشان می‌دهد. فیلترهای «در انتظار بانک»، «ناموفق» و «امروز» برای تطبیق روزانه با پنل بانک آماده‌اند.
- **استرداد:** روی تراکنش موفق دکمه‌ی **Refund** اودو را بزنید. سامان (تا ۵۰ دقیقه)، پاسارگاد و پارسیان وجه را از طریق API برمی‌گردانند. برای ملت و سداد از پنل بانک استفاده کنید.
- **تراکنش «در انتظار بانک»:** یعنی مشتری پرداخت کرده ولی پاسخ تأیید بانک نرسیده. کران «درگاه وستا: تأیید پرداخت‌های در انتظار بانک» هر ۵ دقیقه دوباره تلاش می‌کند. اگر در مهلت بانک تأیید نشود، تراکنش «خطا» می‌شود و بانک وجه را خودش به کارت برمی‌گرداند.
- **مغایرت مبلغ:** اگر بانک مبلغی متفاوت با سفارش تأیید کند، وجه خودکار برگشت داده می‌شود و سفارش تأیید نمی‌شود. این مورد در لاگ با `Amount mismatch` ثبت می‌شود.

## ۷. رفع اشکال

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| ملت ۲۱ یا ۲۴ | شماره ترمینال، نام کاربری یا رمز اشتباه | اطلاعات را از به‌پرداخت دوباره بگیرید |
| ملت ۴۲۱ · سامان ۸ / ۱۸- / ۱۰۶- · سداد ۱۰۰۳ · پاسارگاد ۴۰۱ · پارسیان ۱۲۷- | **IP سرور ثبت نشده** | IP خروجی سرور را از `curl ifconfig.me` روی همان سرور بگیرید و به بانک بدهید |
| ملت ۶۲ · سداد ۱۰۲۳ | آدرس بازگشت خارج از دامنه‌ی ثبت‌شده | `web.base.url` را روی دامنه‌ی ثبت‌شده نزد بانک بگذارید |
| سداد ۱۰۱۸ یا ۱۰۱۲ | ساعت سرور یا کلید تراکنش نادرست | NTP را روشن کنید؛ کلید Base64 را بدون فاصله کپی کنید |
| ملت ۴۱ · سداد ۱۰۱۱ · پارسیان ۱۱۲- | شماره سفارش تکراری | معمولاً از کپی پایگاه‌داده است؛ شماره سفارش وستا یکتاست، پس دوباره پرداخت کنید |
